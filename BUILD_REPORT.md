# Build Report; onjutimeline fork fix-up

Date: 2026-10-22. Branch: `metito/build-fix` (from 62794f3). Scope: get the original 7-slide app (hero / genesis / mint / community / art / live / socials; burgundy, pink, gold) building and running on its own design terms. No dashboard redesign code was ported; only its proven build fixes were borrowed where they applied cleanly.

## Root causes found and fixes applied

1. Missing runtime dependencies. `react` and `react-dom` were imported everywhere but absent from `package.json` (name was the generic `react_repo`, version `0.0.0`). Fix: added `react` / `react-dom` `^18.3.1`, renamed the package to `onjutimeline`, set version `1.0.0`, aligned `react-router-dom` to `^6.30.6` and `vite` to `^6.4.3` (lockfile resolved vite 6.4.5), and added the missing `@testing-library/dom` peer used by the unit tests.
2. Broken thirdweb v5 wiring (the error documented in the committed `tsc_errors.txt`). `src/App.tsx` rendered `ThirdwebProvider` in a tree shaped for a `client` prop that thirdweb v5 does not accept, and `src/hooks/useStore.tsx` carried the client and chain in context typed as `any`. Fix: removed thirdweb from the entry path entirely. A new `src/lib/thirdweb.ts` lazily creates the client and chain (dashboard pattern); `useStore` no longer imports thirdweb or exposes `client` / `chain`; the mint slide wraps its inner component in its own `ThirdwebProvider` and reads the client and chain from the lazy module, so `useActiveAccount` and `ConnectButton` stay inside a provider and thirdweb loads only with the lazy mint chunk.
3. Hard-coded thirdweb client ID. It now lives in `src/lib/thirdweb.ts` as `THIRDWEB_CLIENT_ID`, read from `VITE_THIRDWEB_CLIENT_ID` with the existing publishable key as fallback (masked: `0979...cb80`). A `.env.example` documents the override. The key is a publishable client ID, but rotating it and setting it per deployment is still recommended.
4. Empty `.npmrc`. npm's arborist crashes on this dependency tree (jsdom's optional canvas peer). Fix: copied the dashboard's documented `legacy-peer-deps=true` with its explanatory comment.
5. Unused heavy dependencies. Verified by grepping every import across `src` and `tests`: all 27 `@radix-ui/*` packages, `@hookform/resolvers`, `class-variance-authority`, `cmdk`, `date-fns`, `embla-carousel-react`, `input-otp`, `next-themes`, `sonner`, `tailwindcss-animate`, `vaul`, `zod`, plus `autoprefixer` and `postcss` (no PostCSS or Tailwind config file exists; Tailwind v4 runs through `@tailwindcss/vite`) had zero references. There is no `src/components/ui` directory, so nothing from `components.json` is actually consumed. All were pruned; the dependency set now matches what the source imports. Install size dropped accordingly and `package-lock.json` was regenerated.
6. Scroll-lock race in `src/hooks/useSlideScroll.ts` (pre-existing upstream bug found during QA). The programmatic-scroll lock expired after a fixed 600 ms while multi-slide smooth scrolls were still animating, so the scroll handler hijacked navigation back toward the current slide; deep links such as `/mint` never settled and long navigation-dot jumps stranded midway. A second race let the first scroll attempt fire while the Suspense fallback (one slide wide) was mounted, clamping the target to 0. Fix: the lock is now target-aware and released when the container reaches its target (4 s safety ceiling), and the slide-scroll effect retries at 350 / 900 / 1800 ms so cold deep links land once the lazy slides mount. Verified: `/mint` settles at scrollLeft 2880 and holds; the SOCIALS dot reaches scrollLeft 8640 at `/socials`.
7. Stale artifacts and missing project plumbing. Deleted `tsc_errors.txt` (TypeScript is clean now; the file was also UTF-16 garbled). Added `.nvmrc` (node 20; the sandbox build ran on node 24, and 20 matches the dashboard). Extended `.gitignore` with env files, `coverage/`, `playwright-report/`, and `QA/`. Replaced `vercel.json` with the dashboard pattern: SPA rewrites plus security headers (X-Content-Type-Options, X-Frame-Options, Referrer-Policy, Permissions-Policy, Cross-Origin-Opener-Policy) and immutable caching for `/assets/*`.
8. CI. Added `.github/workflows/ci.yml` (npm ci, tsc, lint, vitest, build on node from `.nvmrc`). Every step was run locally and passes; see results below. Caveat: pushing a workflow file can fail with the known GitHub App limitation (403 "Resource not accessible by integration" when the payload includes `.github/workflows/ci.yml`, because the app lacks the Workflows permission). If the push is rejected, add `ci.yml` through the GitHub web UI. Nothing was pushed from this workspace.

## Remaining caveats

- Console noise in the sandbox QA run was limited to external resource loads the sandbox browser cannot reach (`ERR_TUNNEL_CONNECTION_FAILED` for Google Fonts, IPFS images, and the public RPC used for total supply, plus one favicon 404). These are sandbox network limits, not app errors; the same is true of the placeholder image on the mint card in the screenshot.
- The repo's own Playwright smoke suite (`tests/smoke.spec.ts`) was not run end to end: the pinned `@playwright/test` 1.57 expects a Chromium revision (1200) that is not in the sandbox cache (1248 is), and `npx playwright install` did not fetch it here. Equivalent assertions were covered by the custom headless QA above. On a normal machine, `npx playwright install` then `npx playwright test` should work against the dev server.
- The thirdweb client ID fallback is a publishable key committed in source (as it was upstream); prefer setting `VITE_THIRDWEB_CLIENT_ID` per deployment and rotate if it was ever treated as secret.
- The lazy mint chunk is large (1.46 MB) because thirdweb bundles wallet connectors; further splitting inside thirdweb was left alone to avoid destabilizing the wallet flow.
- Not done, by design: no push to GitHub, no PR, no Vercel deployment. Those steps stay with the parent.
